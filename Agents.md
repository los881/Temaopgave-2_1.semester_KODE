# Project Description

- Build a static portfolio website about drawing, with a homepage and 3 subpages.
- Help affluent, well-educated women aged 45–60 start drawing as a hobby.
- Focus on understanding the hobby, choosing basic supplies, and gaining the confidence to try drawing for the first time.
- Follow the Figma prototype. The website must work on desktop and mobile.
- Pages: `Tegning for begyndere`, `Tegning som hobby`, `Basis tegne-grej`, and `Små tegneøvelser`.

# Technologies

- Use only `HTML5` and `CSS3`.
- Write semantic HTML and structured CSS.

# Project Structure

- Preserve the existing project structure.
- Place HTML files in the project root.
- Place all other website assets in `assets/`, including CSS, images, and fonts.

# Workflow

- Work as a professional UX/UI developer.
- Inspect the existing code and design references before making changes.
- Use the [Figma prototype](https://www.figma.com/design/Wj7usdZr6rHoZimm5oiLgu/Figma-HIFI-prototype?node-id=21-105) and `Temaopgave 2_Analyse-af-Figma-design-skema.odt` as design references.
- Follow the references for colors, `Roboto Condensed`, images, background layers, and components. Adapt the layout and text sizes to the screen width.
- Homepage: 4 text sections, 2 on each side on desktop, stacked in order 1–4 on mobile.
- `Tegning som hobby`: one information section.
- `Basis tegne-grej`: 3 cards side by side on desktop; stack pencils, paper, and the checklist in that order on mobile.
- `Små tegneøvelser`: 4 cards side by side on desktop, stacked in order 1–4 on mobile.
- Place CTA links at the bottom of the content on the homepage, `Tegning som hobby`, and `Basis tegne-grej`. Do not add a CTA to `Små tegneøvelser`.
- Use Facebook and LinkedIn icons in the footer, as shown in Figma.
- Adapt the navigation for mobile. Place footer text and icons on the same row on desktop and stack them on mobile.
- You may create HTML pages, edit HTML and CSS, fix bugs, and improve layout, responsiveness, and SEO within the task scope.
- You may suggest relevant improvements. Only implement changes necessary for the task.

# How CODEX Should Respond

- Respond briefly and precisely in Danish.
- Briefly explain what you changed and checked.
- Report relevant errors, risks, and checks you could not perform.

# Constraints

- The website must not use a database, login, user profiles, backend, payment system, or external APIs.
- Do not add JavaScript, frameworks, libraries, or other technologies.
- Do not guess missing content, files, or link destinations.
- Stop and ask if essential information is missing, references are inaccessible, or instructions conflict.

# Testing and Quality

- Check all 4 pages in a browser on desktop and mobile. Compare them with Figma and the analysis document.
- Check that text, images, and navigation do not overlap or cause horizontal scrolling.
- Check that navigation, internal links, and CTA links lead to the correct pages.
- Give each page a unique `<title>` and a relevant meta description.
- Give informative images descriptive `alt` text and decorative images `alt=""`.
- Use meaningful link text for internal links.
